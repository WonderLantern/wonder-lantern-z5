# 照片画幅（B18）

照片拍摄菜单 → **照片画幅**：关 / 4:3 / 5:4 / 2.33:1。JPG 和 NEF 都按所选比例记录，不是后期裁切。影像区域要选 FX；切到 DX、1:1、16:9 时按原厂拍摄。

| 比例 | L | M | S |
| --- | --- | --- | --- |
| 4:3 | 5352×4016 | 4008×3008 | 2664×2000 |
| 5:4 | 5016×4016 | 3760×3008 | 2496×2000 |
| 2.33:1 | 6016×2576 | 4512×1936 | 3008×1288 |

**B18 起，取景画面由相机自己裁切**：后屏和取景器上的黑框是原厂画的，和原厂 1:1、16:9 的黑框一样。黑框里只显示所选比例的画面，圆的东西仍是圆的。之前那层软件遮罩已经去掉，所以不再需要打开自定义 DISP，也不再有“拍后遮罩出现空框”的问题。菜单里一选完，退回拍摄界面后约 1–2 秒内自动切换，开机时也会自动恢复。不需要切 DX→FX，不需要看一次取景器，也不需要半按快门。

NEF 的 RAW 数据保持原厂 FX 尺寸，Lightroom 和 Adobe Camera Raw 能直接打开。文件里写有 Adobe 裁切信息，打开时按所选比例显示，在裁切工具里可以恢复全画面。NEF 内嵌的预览图是裁切后的。只拍 NEF 时，机内的即时回放、回放和放大都按照片自己的尺寸显示。

## 已知问题

- **只拍 NEF 时，即时回放第一次放大偶尔黑屏或花屏**：再按一次放大就正常。原因是相机有时在即时回放开始前，已经把这张照片的状态改回了全画幅。
- **2.33:1 回放放大时，右下角导航小窗里的图有些形变**。放大后的画面本身不受影响。
- **回放放大只对当前所选比例的照片有效**：例如选着 2.33:1 时，放大 4:3 照片可能提示无法放大。切回对应的比例即可。
- **竖拍照片在机内保持横向显示**，和原厂 16:9 一样。文件的方向标签是正确的。
- **HDMI 输出时的取景没有测试过**。
- 菜单子页每行右边有一个深色小框，这是原厂多行版式自带的。

## 拍照怎么实现

一句话：相机一直工作在 FX，只在拍照那一刻改走原厂 1:1 的裁切流程，并把 1:1 的尺寸换成所选比例的尺寸。

- 原厂每个影像区域都有一套尺寸表：从传感器取哪一块、从哪里开始、L/M/S 各输出多大。原厂 1:1（区域 8）正好是“从 FX 画面里裁一块再输出”，所以借用这条流程。
- 菜单里的 5:4（区域 2）A60–A65 试过直接启用：传感器读出层不支持，会黑屏或锁快门。所以 5:4 也走区域 8 的裁切通道，只借用原厂留在固件里的 5:4 预览尺寸和 5:4 黑框（见下文 B18）。
- 拍照流程：
  1. **模块准备尺寸**：选了画幅并且影像区域是 FX 时，卡上模块把区域 8 的 7 个表指针改为指向内存里自己的表。
  2. **改走裁切通道**：几何配置函数 `0x10142A7C` 的钩子只在“第一次调用、FX、拍照、画幅已开”时，把区域改成 8。
  3. **给出裁切位置**：偏移 `0x1020933E` 和裁边 `0x10143032` 两个钩子按比例给出裁切位置：4:3 左右各裁 332，5:4 左右各裁 500，2.33:1 从第 720 行开始。
  4. **写文件**：主图、NEF 和内嵌预览由相机原来的流程生成。
- 回放和放大：
  - 回放时按照片自己的尺寸判断比例（`0x1034E5E4`），给出正确的预览大小。
  - 只拍 NEF 时，相机会把 RAW 平面当作 FX 处理。所以预览查询、主图记录、解码画布和全尺寸图（`0x10355DCC`）都改成按照片自己的尺寸。
- 没有卡上模块或画幅为“关”时，所有钩子都走原厂路径。画幅选择只存在卡上的 MENU.DAT 里（第 4 字 bit 12–15）。

## 取景遮罩问题的完整解决过程

### 问题

A74–A94 的取景遮罩是卡上模块在自定义 DISP 的绘制末尾画上去的半透明黑条，只填界面层里透明的像素。它有三个先天问题：

1. **拍后遮罩空框**：每次拍完照、从即时回放回到取景时，原厂会先清掉图标所在的矩形再重画图标。清掉后的像素“透明但带颜色”，遮罩把它们当作原厂 UI 跳过，于是在图标位置留下发亮的空框。
2. **改不动**：A89、A90、A92 三次在绘制代码里加读数或改填充规则，扩展显示都会整体停摆。A93 改成“alpha 为 0 的像素都填”，又把回放和放大画面弄坏了。
3. **本质上是盖住**：遮罩下面的取景画面仍是完整的 3:2 FX。原厂界面重画时会和遮罩短暂冲突（闪烁），而且必须打开自定义 DISP 才有遮罩。

所以根本的办法不是再修遮罩，而是让相机自己按比例裁切取景，并画原厂的黑框，就像原厂 1:1 和 16:9 那样。B1–B18 就是这条路。

### 1. 找到原厂黑框（B1–B3）

- **B1 读数**（[`b1_lvwin.inc`](../src/card_module/b1_lvwin.inc)，只读监视 4 段内存）：原厂 16:9、1:1 的黑框来自显示适配函数 `0x1018B4A2` 算出的画面框 `0xC23802F4`。例如 16:9 后屏是 `(0, 36, 720, 442)`，1:1 是 `(120, 0, 600, 480)`。源窗口在 `0xC23802C8 + 0x5E`。
- **离线重放**（[`b1_fit_replay.py`](../src/firmware_hooks/b1_fit_replay.py)）：用实机读出的内存在 Unicorn 里执行原厂 `0x1018B4A2`，结果和实机逐个数字相同。再把尺寸换成 4:3，原厂就会给出 `(40, 0, 680, 480)`，也就是正确的 4:3 黑框。
- **B2 / B3**：把窗口更新 `0x10197FFC` 和显示适配 `0x1018B388` 的区域尺寸查询改接到模块（桩 `hszw` / `hszf`，kind 28），选 4:3 时模块回答 5352×4016。实机上原厂的 4:3 黑框出现了，但**画面被横向压扁**：窗口和黑框都是 4:3，取景画面却仍是整幅 FX，被塞进了 640×480。

### 2. 找到真正的裁切位置（B4–B10）

- **B4**：取景裁切框 `0x10190598` → `0x10188C28` 也接到模块，仍然压扁。说明到这里为止改的都只是矩形和映射这一层。
- **B5 / B6 内存快照**：B5 把 16 MB 内存写进卡，B6 改为在保存测试记录时只抄 8 块关键内存（[`aspect_fw.inc` 中的 B6 快照](../src/card_module/aspect_fw.inc#L661)）。对比原厂 FX 和原厂 1:1 发现，原厂 1:1 是把**整条取景处理链**都换成更窄的输出（`0xC18ED4F8` 1536→1024、`0xC18ED7F6` 1920→1280……），而我们的 4:3 只在最后一级显示时被压成 640 宽。这就是压扁的直接原因。
- **B7 / B8**：改比例种类（`0x10190576`、`0x1019702E`）。只影响预览缓冲和 ISP 模式，不改变处理链宽度，仍然压扁。
- **B9 静态分析**：驱动处理链宽度的是按图像区域查表的三个函数：
  - `ELBY`（`0x101460F2`）：传感器裁切和变形网格输出；
  - `LV_crop_tbl`（`0x10145354`）；
  - `ELBR`（`0x1020949A`）。

  在 Unicorn 里执行原厂变形网格代码验证尺寸：输出必须按 64 对齐，所以 4:3 选 1536×1152，各级缩放比都是精确的 1.0。B9 钩了这几个调用点，模块先调原厂函数，再把几何改成所选比例（[`af_lvsz` 中 ELBY / LV_crop / ELBR 三段](../src/card_module/aspect_fw.inc#L518)）。
- **B10**：B9 实机读数显示 ELBY 命中 0 次。原因是取景实际走的是 `kind = 0x2b` 的另外两个调用点（`0x10146E48`、`0x10146E5A`），补上后**画面不再压扁**。同时在 `-DB2_LVSZ` 下关掉了软件遮罩（[`aspect_mask_ratio()` 返回 0](../src/card_module/custom_disp/aspect_mask.h#L46)）。

### 3. 选完自动生效（B11–B17）

到 B10 为止，选 4:3 后还要手动切一次 DX→FX，原厂才会重算黑框和窗口。

- **B11**：向设置总线发一条“值没变”的通知。取景管理器不处理这种通知，无效。
- **B12**：静态分析发现，取景管理器（`0x101904A8` → `0x1018D014`）收到的每条消息里，只要“设置 0x1624 存在”的标记（消息 `+0x64`）为真，`0x1018CF28` 就会无条件置重算标志。照抄切 EVF 的消息没用，因为那条消息只在显示尺寸真变了时才触发重算（`0x1018BBD6`）。于是固件把 `0x101904A8` 接到模块，模块在需要时往消息里写 `+0x64 = 1`、`+0x68 = 0`，相当于假装切了一次 DX→FX（[`af_lvmsg`](../src/card_module/aspect_fw.inc#L414)）。
- **B13**：B12 实机注入了 0 次。原因是消息每隔 0.4–1 秒才来一批，B12 只等了约 0.45 秒。改为最多等 6 秒、最多请求 3 次，并且只在管理器已激活（`ctx + 4` 非零）时注入（[`a43_watch`](../src/card_module/aspect_menu.inc#L190)）。
- **B14**：B13 关掉 4:3 时，黑框恢复了，窗口却还停在 4:3，随后出现读卡警告。改为黑框和窗口**都**和选择一致才算完成（[`a43_lv_matches`](../src/card_module/aspect_menu.inc#L97)）。**4:3 到此在实机上完全正常。**
- **B15**：推广到 2.33:1。原厂黑框分类 `0x101DC978` 只认 3:2、4:3、5:4、16:9、1:1，2.33:1 会被当成 16:9。所以把管理器唯一的画面框调用 `0x1018D268` 接到模块：先跑原厂，再把 16:9 形状的框改成同宽同中心的 2.33:1（[`af_fit233`](../src/card_module/aspect_fw.inc#L484)）。处理链按 1508×650 裁、输出 1792×768。
- **B16**：B15 后屏花屏。原因是后屏黑框起点 `y0 = 85` 是奇数行，YUV 4:2:0 从奇数行开始会错位。改为对齐到 4（后屏 `(0, 84, 720, 392)`）。
- **B17**：2.33:1 关闭后，退出菜单时画面宽度不变（都是 720），原厂不重算，之后约 3 秒也没有新消息。改为在菜单里一选完就立即请求注入，让退出菜单的那批消息带上标记（[`a43_pick`](../src/card_module/aspect_menu.inc#L337)）。开机时只要选着画幅也会请求一次（[`main.c`](../src/card_module/main.c#L1000)）。**4:3、2.33:1 的打开、关闭、开机全部自动切换。**

### 4. 加入 5:4（B18）

- 原厂固件里完整保留了尼康原生的 5:4 资产：kind 2 的预览表（600×480、1350×1080、150×120、468×375）、ISP 比例映射，以及 `0x1018B4A2` 的原生 5:4 黑框分支。只是传感器读出层没有配原生区域 2。A81 起，固件里 kind 2 的 8 处预览表被改成了 2.33:1 用。
- B18 把读取这些预览表的 7 处（4 个预览选择函数 `0x102092FA`、`0x10209304`、`0x1020930E`、`0x10209318`，3 处拍照预览缓冲 `0x10143572`、`0x101435D4`、`0x10143F2E`）接到模块（[`af_pvw54`](../src/card_module/aspect_fw.inc#L584)）。选 5:4 时，模块换回尼康原厂的 5:4 条目；其他情况下桩原样执行原厂指令。
- 取景：窗口 `(500, 0, 5516, 4016)`。黑框直接由原厂的 5:4 分支画出，不需要软件改框。ELBY 1256×1006（起点 126），输出 1280×1024；ELBR 640×512。
- 菜单「照片画幅」扩为 4 行：关 / 4:3 / 5:4 / 2.33:1。

### 结果

| | 遮罩（A74–A94） | 原生取景（B18） |
| --- | --- | --- |
| 黑框 | 模块在界面层上画半透明黑条 | 原厂画面框，和原厂 1:1、16:9 一样 |
| 取景画面 | 整幅 3:2，被盖住两边 | 处理链按比例裁切，不变形 |
| 拍后空框、闪烁 | 有 | 没有 |
| 需要自定义 DISP | 需要 | 不需要 |
| 切换 | 立即 | 退回拍摄界面后约 1–2 秒，开机也自动 |

### 走过、但不要再走的路

- 只改源窗口或画面框：画面仍压扁（B2–B4）。
- 只改比例种类：处理链宽度不变（B7、B8）。
- 发“值没变”的设置通知：取景管理器不处理（B11）。
- 照抄切 EVF 的那条消息：后屏上不触发重算（B12）。
- 往卡上写 16 MB 内存镜像：太慢，还出过读卡错误（B5，改用 B6 的小快照）。
- 在遮罩绘制代码里加读数或改结构体：扩展显示整体停摆（A89、A90、A92）。
