# Z 5 竖拍界面：实现说明与移植指南

更新于 2026-11-10。本文说明如何在尼康 Z 5（单 EXPEED 6，固件 C 1.50）上实现“竖着拿相机时，取景信息和 i 菜单跟着转”，以及其他单 EXPEED 6 机型想复现时要做什么、难在哪里、哪些要重新设计。

文中的地址都属于 Z 5 C 1.50 的 MAIN 模块（基址 `0x10020000`），其他机型和其他固件版本一律不能照搬。

## 1. 现状

当前版本：固件 `f8ffd4ad…`、卡上模块 `449534c4…`，由 `patch.py` 生成。

| 项目 | 状态 |
| --- | --- |
| 两侧竖拿（手柄朝上、朝下）时取景信息转为竖版 | 实机通过 |
| i 菜单 6×2 改为 4×3，方向键跟着屏幕转 | 实机通过 |
| i 菜单打开的设置页（ISO、白平衡、优化校准、HDR、测光等）转正、居中，方向键换向 | 实机通过 |
| ISO 这类长条，选中项保持在中间 | 实机通过 |
| 竖版直方图（直方图页、直方图水平仪同框页） | 实机通过 |
| 放大取景、回放前的黑屏、转波轮时的弹层 | 实机通过 |
| 取景器（EVF）、HDMI | 不做竖版，保持原厂横版（见第 7 节） |
| 视频模式 | 没有专门判断，录视频前建议关掉“竖拍显示” |
| 触摸屏坐标 | 没有跟着转 |

实机验证只有作者的一台 Z 5，限照片模式、背屏。功能默认关闭，在设定菜单“竖拍显示”里打开。

## 2. 思路

Z 5 的界面由 GUI 任务生成一串绘制命令，再交给 OpenVG 执行。命令种类很少：画图像、画矩形、清除区域、画圆角框、画文字。每条命令都带着横版坐标。

我们没有去改每一个界面的布局代码，而是在这几种绘制函数的入口截住命令：

1. 读相机朝向；横拿时什么都不做。
2. 根据元素的原始位置，查一张“横版位置 → 竖版位置”的换算表。
3. 把坐标改成竖版位置，再把整块内容旋转 90° 或 270°，画到物理上仍是横向的屏幕上。

这样原厂的每个界面都还在正常运行，我们只改“画在哪里、朝哪个方向”。原厂没有改过的界面会保持横版，而不会坏掉。

## 3. 结构

和本项目其他功能一样，分成两部分：

- **固件（MAIN）：** 只加 12 个很小的入口。每个入口先找卡上模块，找不到或开关关闭时，执行被替换的原指令，回到原厂路径。
- **卡上模块：** 朝向判断、页面识别、换算表、按键换向、直方图绘制都在这里，改逻辑不用重刷固件。

入口的进入方式：在函数开头把 4 字节换成跳转，经 `0x105BA2C4` 起一段原本为零的空隙里的跳板，进入追加在 MAIN 末尾的桩代码。桩代码通过开机时清零的锚点找到模块的状态块，校验标记后调用模块里的函数，把寄存器原样传过去。模块可以改写寄存器和描述符，也可以要求跳过原调用。

| 入口 | 地址 | 用途 |
| --- | --- | --- |
| 图像 1 | `0x104A673C` | 大部分图标；描述符带角度字段 |
| 图像 2 | `0x104A7292` | 整层复制；小图也走这里 |
| 图像 3 | `0x104A7AC2` | 不读角度，必须改走图像 1 |
| 矩形 | `0x104A5EDC` | 背景、高亮、线条 |
| 清除 | `0x104A641E` | 擦除区域 |
| 圆角框 | `0x104A629C` | 按钮外框 |
| 文字 | `0x1056A5EE`（调用点） | 字形的 3×3 变换矩阵 |
| 光标设置 | `0x10411418` | i 菜单格子的光标 |
| 动作分发 | `0x1031239E` | 方向键等动作码 |
| 路径 ×3 | `0x104A6064`、`0x104A65BE`、`0x104A7F8E` | 诊断用，只观察 |

另外，直方图水平仪同框的取数判断改成也接受一个新的掩码位（见第 6 节）。

## 4. 关键技术点

### 4.1 朝向

`0x101EA71E` 是原厂的朝向读取函数，返回 0 = 横拿、1 = 手柄朝上、2 = 手柄朝下、3 = 倒置。这个函数是按 Z30 上已知的同类函数的指令序列搜出来的，含义在实机上逐一确认过。

### 4.2 改写各类绘制

| 类型 | 做法 |
| --- | --- |
| 图像 | 描述符 `+0x18` 是目标框，`+0x40` 是角度。按换算表改目标框，角度设为 90 或 270。原厂的“按源尺寸绘制”模式在 90°/270° 时缩放会出错，所以改成按目标框绘制 |
| 图像 3 | 渲染时根本不读角度。在入口把描述符转换成图像 1 的格式，调用图像 1，再跳过原调用 |
| 矩形、清除、圆角框 | 路径图元没有角度，只能交换宽高、重新算位置 |
| 文字 | 改字形矩阵：平移到竖版位置，再乘上 90° 旋转 |
| 整层复制 | 720×480 的整层复制不能改，否则整页会错位 |

### 4.3 只改屏幕层

相机会先把某些内容画到离屏缓冲，再整张贴到屏幕上，例如转波轮时弹出的数值条。如果连离屏内容也一起改，贴上来就是白框和噪点。所以只在当前绘制目标是屏幕层（目标 2）时才改写；目标号在 `0xC18085D4`。

### 4.4 布局

布局不是按功能逐个写的，而是按位置分区：

- **取景页：** 一张按原始坐标划分的分区表，每区给出竖版位置。表是用多张实机照片反推、反复修正出来的。分区判断用元素的中心而不是左上角，这样图标、外框和它的清除区域会一起移动，不会留下残影。
- **i 菜单：** 按格子编号把 6×2 重排成 4×3，和格子里放了什么功能无关，36 种可选项目都适用。
- **设置页：** 整页平移到竖屏中间，底部按钮栏按实际按钮宽度居中。宽于竖屏的内容分两种处理：
  - **每次都整排重画的页面（如 ISO）：** 横向滑动，让选中项保持在中间。
  - **只重画有变化的格子的页面（白平衡、优化校准）：** 滑动会让没重画的格子留下黑块，所以改为整排按 2/3 缩小到竖屏宽度。
- **全屏绘制：** 宽高都接近整屏的矩形和清除保持全屏，例如回放前的黑屏。

### 4.5 识别页面

`0xC18289DC` 的 UI 模式区分取景（0）和 i 菜单（3）。i 菜单打开的设置页仍是 3，要靠绘制特征区分：主菜单背景框固定是 `0,54,720,146`，设置页有自己的大背景框。白平衡和优化校准的 UI 模式是 10 和 1，这一点是靠实机读数确认的。

### 4.6 方向键

- **i 菜单格子：** 在光标设置函数里，按按下的物理键和朝向，重新计算目标格子。
- **设置页：** 在动作分发入口换掉动作码（右 2、左 3、上 4、下 5）。例如手柄朝下时，物理“上”变成“右”。

### 4.7 转动后重画

原厂只在需要时重画，转动相机不会触发。模块在朝向变化时模拟一次约 0.12 秒的半按快门，让取景页整页重画；同时把下一次清除扩大到全屏，擦掉横版的旧内容。副作用是转动时可能触发一次对焦。

## 5. 直方图

Z 5 的直方图不是用 OpenVG 绘制命令画的，所以第 4 节的方法转不了它。实机读数显示，切到直方图页时，所有绘制入口在直方图区域都没有调用；推测是相机直接把像素写进显示缓冲，再由硬件叠加。

所以我们的做法是：竖拿时隐藏原厂直方图，自己画一个。

1. **数据：** 相机把 256 档亮度计数（每档一个 32 位整数）从 `0xC202A55C` 复制到 `0xC2028DE8`，算出显示用的峰值（最大值和 4 倍平均值中较小的一个），存到 `0xC20280C8`（`0x1034B914`）。这个位置是用卡上模块在相机上扫描内存、对比亮暗两个场景找到的，再用这段固件代码确认。
2. **隐藏原厂直方图：** 直方图控件有 9 个显示掩码，在 RAM 的 `0xC1826118`。竖拿时清零，横拿时恢复原值。
3. **绘制：** 模块在屏幕层的清除命令旁边，最快每 80 ms 读一次计数，每 4 档合成一根柱，共 64 根，调用原厂的矩形和清除函数画在竖屏上。调用时设一个标志，让自己的绘制直接穿过钩子。模块里不能用编译器的除法辅助函数，所以带了一个移位除法。

## 6. 直方图水平仪同框

同框是本项目早先的功能：原厂只在直方图页（DISP 2）取直方图数据、显示控件；固件在这两处判断加小钩子，当显示掩码的第一个字有第 3 位（`0x444` → `0xCCC`）时，水平仪页（DISP 3）也放行。

竖拍时出现了冲突：第 3 位同时决定“水平仪页要不要取数”和“原厂直方图要不要显示”。清零，竖版直方图就没有数据；保留，原厂横版又会显示出来。

解决办法：在这个判断里加一条指令，把第 27 位移到第 3 位再测试，也就是同时接受第 3 位和第 27 位。64 个控件的 576 个原厂掩码只用到前 24 位，所以第 27 位不会影响任何控件的显示。竖拿时模块只写第 27 位，相机继续取数，原厂横版不显示。构建时用 Unicorn 对比了 256 个 DISP 值下的执行结果。“第 27 位不影响显示”来自掩码统计，没有找到显示判断函数直接证实，但实机效果符合预期。

竖版直方图在直方图页放在右侧中部，在水平仪页放在右上角，避开中间的水平仪圆盘。

## 7. EVF、HDMI 和视频：为什么不做，怎么处理

**不做的原因：** EVF 的界面布局和背屏不同，元素的位置、大小、顺序都不一样，要另做一整套换算表；HDMI 的画布是 960×544，同样需要另一套。工作量和背屏差不多，收益不大，所以决定竖拍只在背屏生效。

**怎么处理：** 不做竖版，也不能让它错乱，所以必须可靠地识别并关闭。

- **EVF：** 相机在 EVF 显示时会用到 15～19 号绘制目标，背屏时没有（实机读数）。模块只要看到这些目标，就在 3 秒内停用竖拍，EVF 保持原厂横版；离开取景器 3 秒后恢复竖版。自动切换（眼睛靠近或离开）实测正常。
- **HDMI：** 模块遇到 960×544 的 10 号目标时不做竖版。实测接 HDMI 时竖拍不起作用，保持原厂画面；是不是正因为这一条，没有单独查过。
- **视频：** 没有找到视频模式的判断，录视频前建议关掉“竖拍显示”。

## 8. 开发方法和教训

- **先读数，再改固件。** 有两轮对绘制路径的推测上机后被推翻。之后改为让卡上模块把内部状态显示在“我的菜单”最后一行，在实机上直接读，再决定固件怎么改。读数不能在页面切换时清零：有一次读数在打开菜单的瞬间被清零，全是 0，差点得出错误结论。
- **模块代码不能依赖只读数据段。** 模块代码被复制到运行地址执行，只读数据段不会跟着复制。一段三元表达式链被编译器转成了查表，方向键一度全部失效；改成立即数移位后恢复。
- **模拟器的边界。** 模拟器能验证菜单、按键、大部分绘制和“开关关闭时和原厂逐字节一致”，但画不出直方图、波轮弹层、放大取景、EVF，这些只能实机验证。模拟器的时间比例也和实机不同，例如重画间隔，不能直接当作实机数据。
- **开关关闭时必须和原厂一致。** 每一版都在模拟器里比对 i 菜单 8 键的画面哈希，并用 Unicorn 检查改过的固件判断。

## 9. 其他单 EXPEED 6 机型如何复现

适用对象：Z 6、Z 7、Z 50、Z fc、Z 30 这类单 EXPEED 6 机型。Z 6II、Z 7II 是双 EXPEED 6，任务结构不同，不在本节范围。以下除了明确标出的，都是基于 Z 5 经验的判断，没有在其他机型上验证。

### 9.1 前提条件（最难的部分往往在这里）

1. **能解开并重新封装固件。** 本项目用 z5mod 的解码器，它只支持 Z 5 C 1.50。其他机型要有对应的解码和校验方法。
2. **能从存储卡加载并运行代码。** 本项目的逻辑都在卡上模块里，靠 z5mod 的加载器和 SDK。没有加载器，就只能把全部逻辑写进固件，每改一次都要重刷，迭代成本会高很多。Z 30 有 wonder-lantern-z30 可参考。
3. **一个能跑菜单和按键的模拟器**，很有帮助但不是必需。没有的话，每一步都只能上机试。

### 9.2 可以直接沿用的

- 整体思路：截住绘制命令、按位置换算、旋转。
- 固件和模块的分工：固件只加入口，开关关闭时走原厂路径。
- 各类绘制的改写方法（第 4.2 节）、只改屏幕层、重画方式、直方图的“隐藏原厂、自己画”。
- 用读数而不是推测来定位问题的方法。

同一代 EXPEED 6 固件的 GUI 和 OpenVG 层很可能结构相近，绘制函数的种类和描述符格式可能一样，但这需要在目标机型上确认。

### 9.3 必须重新定位的

所有地址都要在目标固件里重新找，不能按偏移推算：

| 项目 | 找法 |
| --- | --- |
| 绘制函数入口和分派函数 | 从 OpenVG 函数表和 `vgDrawImage` / `vgDrawPath` 的调用者往上找；分派函数按命令 ID 分支 |
| 文字矩阵的调用点 | 找文字对象载入 3×3 矩阵的那次 `vgLoadMatrix` 调用 |
| 朝向读取函数 | 按指令序列特征搜索；Z 30 上已知是 `0x1021B5F6` |
| UI 模式、当前应用、DISP 页 | 用模拟器或实机读数，对比切换前后的内存 |
| i 菜单光标、动作分发和动作码 | 在模拟器里对光标设置函数下断点，看调用栈 |
| 绘制目标表 | 分派函数取视口尺寸时读的那张表 |
| 直方图数据和控件掩码 | 先找控件描述符表，再找复制 256 档计数的循环 |
| 可用的空隙和追加空间 | 跳板需要一段确认无人使用的零填充区 |

### 9.4 必须重新设计的

- **取景页换算表：** 每台机型的信息布局不同（Z 6 / Z 7 的信息更多，Z 50 / Z fc / Z 30 的图标位置也不同）。要拍横版和竖版的实机照片，逐个元素确定竖版位置，再反复上机修正。这是工作量最大、最需要耐心的部分。
- **i 菜单：** 格子数和尺寸可能不同，重排规则要重算。
- **页面识别的常数：** 主菜单和设置页的背景框尺寸、各设置页的 UI 模式值都要重新读出来。
- **按键换向：** 动作码可能不同；有子选择器或额外拨盘的机型还要考虑这些输入。
- **屏幕结构：** Z fc 和 Z 30 是侧翻屏，Z 50 是可向下翻转 180°的屏，翻转自拍时原厂本身就会改变画面方向，要先弄清原厂的处理，避免两套旋转叠加。Z 30 没有取景器，EVF 那部分可以省掉。
- **直方图：** 如果目标机型的直方图也不经过 OpenVG，就要像第 5 节那样找到数据自己画；如果经过，反而更简单。

### 9.5 难度

| 难度 | 内容 |
| --- | --- |
| 低 | 朝向读取；图像和矩形的改写原理；开关关闭时回到原厂 |
| 中 | 绘制入口、跳板和桩代码；取景页换算表；i 菜单重排；转动后重画 |
| 高 | 设置页的识别和布局（种类多、刷新方式不同）；方向键换向；直方图；离屏内容；每台机型都要大量上机核对 |
| 最高 | 没有固件解码器或卡上模块加载器的机型，要先解决这两项 |

### 9.6 建议步骤

1. 确认固件解码、重新封装和刷回原厂这条路是通的，并且能从卡上运行代码。
2. 找到朝向函数，做一个只显示朝向读数的卡上模块，在实机上确认含义。
3. 找到绘制分派和各类绘制函数，在模拟器或调试环境里做一次“强制全部旋转”的实验，确认改写方法有效。
4. 只加入口、不改画面，确认开关关闭时和原厂完全一致。
5. 先做 i 菜单（规则最整齐），再做取景页换算表，用实机照片逐轮修正。
6. 再做设置页、方向键、重画、直方图。
7. 最后处理 EVF、HDMI、视频：做竖版，或者像本项目一样识别后关闭。

**风险提醒：** 刷入修改过的固件有使相机损坏的风险。每一步都应保留回到原厂的办法，并先在不改画面的状态下确认相机正常。
