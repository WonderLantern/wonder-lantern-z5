# 自定义 DISP 整页基底接管：调查与 L39 实现

2026-11-17。针对 L38 上自定义 DISP2 直方图柱子慢、经常为空及闪烁的反馈，检查能否统一使用原厂 DISP0／DISP1 绘制基底。调查阶段只读分析两份既有 MAIN；用户随后授权实现，L39 已加入纯卡模块接管。全程未修改固件补丁，未执行 ARM、QEMU 或相机测试。

## 结论与实施边界

**有不新增固件钩子的实现候选：插件管理逻辑 DISP 页号，原厂实际页号固定为详细页 0。** 当前第 108 组固件已有可修改按键参数的入口，可以在原厂 DISP 切页前接管。它需要改造切页与配置选择，不能仅替换一个页面对象指针。L39 实现改用下述 RAM 普通拍摄按键回调，不能据此宣称直方图问题已实机修复。

用户随后选择简化配置：只保留一个自定义 DISP 总开关，打开后 DISP0～DISP3 全部使用自定义配置，不再逐页选择是否接管。每页只设置水平仪、直方图和详细信息。关闭总开关后恢复原厂切页及显示许可。本文以下按此方向记录；先前讨论过的“部分页自定义、部分页原厂”和“详细信息关时实际切到 DISP1”均不作为当前首选方案。

现有方案保留原厂实际页号，只投影控件显示许可；新的候选方案需要分开两种状态：

| 状态 | 用途 |
| --- | --- |
| 逻辑页号 0～3 | 用户 DISP 循环、各页水平仪样式、直方图和详细信息配置；没有逐页接管开关 |
| 原厂实际页号 | 总开关开：逻辑页 0～3 均取 0；总开关关：原厂自行切页 |
| DISP4 | 保留原厂关闭显示及返回流程，不能映射成普通简单页 |

这样原厂从生成快照开始就按 0 工作，避免自定义逻辑 DISP2 进入原厂直方图专用分支，及逻辑 DISP3 进入原厂水平仪专用分支。详细信息关闭时，给实际 DISP0 投影未修改的 DISP1 显示许可，保留简单页基础信息与电池，不改变原厂实际页码。原版水平仪仍需沿用现有主动 pose/show 入口，TypeA 和自制直方图仍在共用尾部绘制。不增加整屏图像缓存，不在稳定刷新时反复使整页失效。

不能只在每次按键时把原厂即将进入的页号改成 0：下一次原厂仍从实际 0 推进，会反复认为下一页是 1。插件需要先推进独立的逻辑页号，再应用该逻辑页的配置；同为实际 DISP0 的逻辑页切换也要触发必要的局部清理和原厂更新。

## L39 最终采用的 RAM 回调入口

后续静态检查确认普通拍摄 UI 对象为 `0xC18289E0`，RAM 初始化映像中 `+0x14` 为 `0x10304109`，`0x10311F40` 将该对象放进普通 UI 表。`custom_disp/route.inc` 比较替换 `0xC18289F4`，包装普通拍摄按键处理；所有其他按键和禁用状态转发原函数。它不使用空操作键，也不依赖旧 MAIN 缺少的 kind=8 钩子，因此此前该钩子的兼容限制不适用于最终 RAM 包装方案。两份 MAIN 的回调初始化和新依赖均由构建器分别校验，完整功能仍需实机确认。

接管 DISP 保留 `0x10304108` 的前置、后置处理，并调用原厂 `0x10341AAA` 一次作可切页检查及设置事件标记。原厂成功选择 1（从实际 0）或 0（从实际 4）后，插件推进逻辑页，在 `0x1030D744` GUI 更新前将实际页映射为 0 或 LCD 4；中间简单页没有进入 GUI 绘图。LCD 进入 4 仍通过 `0x1042DE0A` 对原厂 UI 对象执行原关闭显示动作，EVF 跳过 4。原厂服务返回后复查输出和应用，避免写错输出。

MENU.DAT 采用 16 字节 D8+CD50，保存总开关与两端逻辑页，读取兼容旧 8/12 字节。GUI 基底稳定时不反复写原厂设置；接受切页后才保存页号，不依赖关机回调。检测到原厂其他操作改变页号时接纳变化，避免本机唤醒后被逻辑 4 再次强制熄屏。实现和设置详情见 [CUSTOM_DISP_HANDOFF.md](CUSTOM_DISP_HANDOFF.md)。

下列调用链为调查依据；“实施前仍需解决”保留最初排查清单，L39 的静态／宿主验证不代表这些组合已完成实机验收。

## 原厂实际读取链

当前卡模块包装 `0xC1821718` 回调数组的第 1 项，原值 `0x102F5DF5`。该函数按事件号分派，事件 9 转到 `0x102F5D92`。控制器内部调用快照生成及 GUI 分派，不会把卡模块预先改过的快照当作不可变输入。

快照生成 `0x10342826` 在 `0x10342992` 调用 `0x10341A60` 选择设置键，再经 `0x10456098` 读取，将结果写到拍摄快照 `+0x18E`，即 `0xC2028442`。随后仍在快照生成函数内，`0x10342E22` 直接调用原厂直方图取数流程 `0x1034B8EC`。因此只在外层回调入口改快照页号，会在取数之前被原厂覆盖；到第一个绘图控件才改则已经错过本轮取数。

`0x10341A60` 先检查设置 `0x168C`，再检查显示输出 getter `0x1045509E`。普通照片模式的 LCD／EVF 分别选择 `0x3B15`／`0x3B16`；另一模式分支使用 `0x3B17`／`0x3B18`。后两项不能当作插件空闲存储使用。

| 设置键 | 固定属性描述符 | 4 字节 RAM 数值 |
| --- | --- | --- |
| `0x3B15` | `0x115CD4EC` | `0xC253DFBC` |
| `0x3B16` | `0x115CD4FC` | `0xC253DFC0` |
| `0x3B17` | `0x115CD50C` | `0xC253DFC4` |
| `0x3B18` | `0x115CD51C` | `0xC253DFC8` |

属性读取链为 `0x10456098 → 0x10234AD2 → 0x10198F72 → 0x10199648 → 0x100B6520`；属性索引由 `0x100B64F0` 解析。上述四个描述符均为类型 7、长度 4，读取实现直接从描述符指定地址载入数值，没有发现可单独替换的 RAM getter 回调。此结论限于这条已追踪的读取链，不是对所有原厂扩展机制的否定。

## 为什么显示许可不等于整页接管

`custom_project_mask()` 关闭组 32 的自定义页可见位，但不改变快照中的实际页码：

- 原厂取数 `0x1034B8EC` 经 `0x1042E1BA` 按快照 DISP 页码判断，允许 DISP2 时仍会调用 `0x10456B34`，与插件独立工作任务使用同一统计入口。隐藏控件并未消除这次原厂调用。
- 原厂控件配置 `0x10348294` 也按页码分支，在 `0x103482C0` 后主动配置组 32 的显示状态，在 `0x103482DE` 等位置直接写控件字段。不能认为设置 descriptor mask 后此路径就完全不运行。
- 原厂 `0x10343810` 比较当前与上一份快照的页码；页码或其他拍摄状态改变时会失效显示快照。每轮把 2 改成 0、结束又改回 2，会破坏这套比较的含义。

这些静态行为说明当前 DISP2 没有被真正替换。重复调用统计和原厂控件介入是本次慢／空白／闪烁的排查线索；没有实机调用追踪，不能证明其是唯一根因，或证明统计接口一定被并发调用、返回零包。

## 卡模块现有的输入接入点

当前固件的 `0x1031239E` 已经接入 `z5_vui_hooks.py` 的 `kind=8` 按键入口，最终调用常驻 `cm_t.vui_fn`。入口保存寄存器，卡模块可通过参数数组修改原厂接下来接收的键值。目前它用于竖拍方向键适配；若用于自定义切页，接管判断必须放在 `!c->vui` 等竖拍开关提前返回之前，并保持菜单和其他应用输入原样转发。

普通拍摄按键分派的表项将键 `0x29` 导向 `0x10303F64 → 0x10341AAA → 0x1034B872`。原厂循环表 `0x10748A10` 的前五项对应 `0→1→2→3→4→0`。原厂切页函数还检查临时 UI、模式等状态，不能只照抄五项循环就替代全部逻辑。

原厂页设置函数 `0x10341A92` 同时更新快照页码和对应设置，使用 `0x104560A4` 写设置。进入页 4 时，原厂 `0x1034B872` 还会调用 `0x1042DE0A` 处理显示状态，返回值也不同。实现时应保留这部分行为及按键可用条件。

因此，候选改造是：输入入口识别正常照片取景的 DISP，在总开关打开时推进插件逻辑页，逻辑页 0～3 让原厂实际停在 0，并应用目标逻辑页的显示许可和扩展配置；只在逻辑页或配置变化时失效必要 UI；让后续完整原厂快照、布局、更新、绘制、提交看到稳定的 0。插件各处通过逻辑页读取配置，而非再以 `0xC2028442` 直接索引四页设置。DISP4 的进入与退出保留原厂显示状态处理；关闭总开关时需要将逻辑页恢复为原厂实际页，不能将用户永远留在 DISP0。

没有确认“改成键 0”是无副作用的吞键方式。后续实现必须验证选用的空操作键或包装原厂 UI 按键处理器的方式，不能直接假设零值会跳过原厂输入。

## 不采用逐帧临时篡改原厂设置

虽然已定位四个 RAM 数值地址，但每帧写成 0／1、画完再恢复并非透明操作：设置值属于全局，GUI 可能等待图形服务或其他任务；另一个读取者可能看到临时值。恢复时也可能遇到原厂刚切页、切输出或修改设置。比较后恢复只能避免部分覆盖，不能阻止其他任务在窗口内读取或持久化临时值。因此不能以“最后恢复了”证明它不会影响切页和保存。

若未来要求既保留原厂真实 DISP2／DISP3 身份，又只给绘制提供另一页号，更直接的办法是在原厂页码读取／快照生成处加入明确的模块回调。当前未发现该位置已有可用回调，本次没有修改固件来添加它。

## 实施前仍需解决

- LCD／EVF 各自逻辑页状态、输出自动切换与初次进入；不能再让工作任务按实际基底页读取另一页的开关。
- 逻辑页在正常关机／冷启动后的恢复。旧 L38 设置格式严格接受 8／12 字节；L39 已明确兼容迁移并扩展保存为 16 字节，不能借用视频 DISP 设置，也不能无依据占用文件位或每帧保存。
- 总开关与旧逐页配置的迁移规则、菜单结构需要一起修改。旧设置中的逐页启用位不能继续作为新运行时的接管条件；总开关关闭只停用接管，不清空各页配置。
- 原厂可切页条件、DISP4、半按、放大、i 菜单、临时 UI、视频及拔卡后恢复原样。
- 基底相同但逻辑页不同的切换，仍需清理旧直方图／笔画并更新显示；原厂当前／上一份快照必须始终反映实际基底，不能每帧伪造一次切页。
- 废除或改写当前逐页 mask 投影：原厂基底为 0 时，实际使用的是逻辑页的配置，不能继续混用逻辑 DISP0 的 flags。
- 对新增原厂依赖做固件指纹和保留映像检查，增加真实 C 切页／恢复宿主测试，再构建和实机测试。宿主测试不验证 GUI／ISP 时序和物理 fps。

## 验证范围

在当前 MAIN `6389847f…604bf` 与旧 MAIN `e7e4ec54…24d61` 上静态核对了四个属性描述符、快照读取调用、事件 9 分派、键 `0x29` 的分派及五项切页表，结果一致。旧 MAIN 的 `0x1031239E` 仍为原厂入口，没有当前固件已有的按键钩子，**不能将此纯卡模块候选路线直接声称兼容旧实验固件**。
